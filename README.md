# AMD Agent

AMD Agent 是一个以 Electron、React 和 TypeScript 实现的多模型智能体桌面应用。当前实现已经把模型配置、路由、流式执行、指标、项目上下文、受控命令执行和发布验证链路接通；含代码的回答会执行静态审计并写入哈希链与指标库。

版本号以 [package.json](package.json) 为准，发布变化见 [CHANGELOG](CHANGELOG.md)。本轮优化的交付与验证记录见 [实施进度](outputs/27-OPTIMIZATION-PROGRESS.md)，历史设计和验收见 [文档索引](docs/INDEX.md)。所有页面共享系统明暗主题：浅色白底深字，深色黑底浅字；切换系统外观时即时更新。

## 当前能力

- 沉浸式桌面工作台（界面规范见 `DESIGN_SYSTEM.md`）：顶部全局栏左侧保留 macOS 交通灯，中间仅显示会话标题，右侧显示已打开文件的 Tabs 与文件面板开关；左侧竖列导航（工作台/运行监测/设置），会话侧栏顶部为铃铛/搜索/NewAI 品牌工具栏，中间任务对话。右侧工作区默认隐藏；点击顶部文件面板开关后显示约 270px 文件树，点击具体文件才展开「代码预览 + 文件树」双栏；关闭预览恢复单栏，再收起面板隐藏工作区。工具/子智能体过程只在运行中显示，复制/编辑默认隐藏。
- 外观跟随系统明暗主题：白天白底黑字，夜间黑底白字，界面除图标外不再使用强调色。
- 每个会话可切换“多模型/单模型”：多模型由应用根据任务选择模型并按需规划；单模型时选择固定模型执行，跳过语义分类、规划与子智能体。
- 权限模式：设置 →“运行与权限”可选择请求批准、帮我批准或完全控制。命令经过分类与平台沙箱包装，系统管理类操作始终需要确认；工具信任可以逐项设为询问、允许或禁用，写入和命令工具仍由权限模式统一管理。
- 本地项目：在「新建项目」弹窗中选择文件夹，自动推断名称并读取 Git 分支和项目类型。最近打开的项目保存在 `projects.db`，只保存路径和名称；从列表移除不会删除文件。
- OpenAI、Anthropic、Google 统一调用接口；没有 API Key 的内置模型不会参与路由，也不会返回演示答案。自定义 OpenAI-compatible 本地服务可以按需不配置 Key。
- SQLite 持久化模型配置、会话历史与运行指标。
- API Key 和端点查询参数中的凭据使用 AES-256-GCM 加密；桌面端通过 Electron `safeStorage` 持久化加密密钥，避免重启后无法解密。
- 启发式路由：按任务类型、复杂度、能力评分、优先级和成本选择启用模型；高复杂度任务会将综合智能度纳入评分。
- 含代码的模型回答会执行确定性的静态代码审计，结果写入 `audit.jsonl` 哈希链和 `metrics.db`，监测面板显示“代码审计通过率”；纯文本回答不审计，也不增加额外模型调用或延迟。
- 操作级审计：文件写入、命令执行（审计仅保留可识别的命令与常用任务名）和手动停止进程写入 `operations.jsonl`（只追加、30 天保留），在“运行监测”页的「操作审计」中查看和复制 JSON；与代码审计哈希链分开保存。
- 运行检查点：每轮工具完成后在 `checkpoints.db` 记录次数、最后工具与已修改文件；应用重启时把所属实例已经退出的未完成任务标记为中断，会话内显示“上次任务在 N 次工具操作后中断”，可选择知悉；不做自动重放。
- 按角色分工：复杂任务或指定规划策略可调用能力匹配的模型生成 JSON 建议，由应用校验只读子任务（最多 4 个），执行与汇总继续使用已选执行模型。DeepSeek 与其他模型同等参与，可在运行设置中指定规划、摘要与归档模型；可关闭额外规划，失败时继续普通路由。
- 可选本机 Ollama 分类：运行设置中独立选择分类模型，原生 JSON Schema 输出、短超时与取消、后台预热、忙时/离线/缺模型回退规则和失败熔断；不下载权重、不将分类模型加入回答候选。
- 分类反馈：运行监测展示本轮分类及来源，主动纠正后在本机保存已确认样本，用作后续相关任务的少量分类示例；可导出 JSON。未确认观测只留在有界内存中，不把执行成功当作正确标签，也不训练模型权重。
- 高复杂度任务支持双模型协作：先由单独的推理模型生成计划，再由任务类型和能力评分选出的执行模型完成任务；低/中复杂度任务只调用一个执行模型。
- 调用链轨迹：每个用户 turn 有独立 `runId`，记录路由、上下文压缩、记忆检索、规划、模型尝试、工具、合成、审计和验证的父子 span；在“运行监测”页面查看跨会话运行列表、成功率/成本/延迟、模型分布和可筛选/展开的调用链，支持 JSON 导出；启动时自动清理 30 天/1,000 条之外的 trace。
- 上下文压缩与长期记忆：按模型上下文预算装配历史，旧轮次生成增量摘要（可回退到确定性摘要），工具结果以 digest 进入后续上下文；长期记忆支持全局/项目范围、FTS5 检索和 `remember`/`recall`/`forget` 工具。当前版本暂时隐藏长期记忆入口（数据库与已有数据保留），避免在未确认使用习惯前暴露配置。
- 工具调用策略：每轮工具调用次数、总输出字符、单工具超时和结果截断；只读工具支持 TTL 缓存；新增 `process_list` 找回后台进程。
- 路由规则与配额：支持 `<userData>/routing-rules.json` 规则；设置 →“运行与权限”→“打开路由规则”进入逐字段表单（任务类型/复杂度/关键词/主模型/策略/协作/fallback，可切回 JSON），保存前归档历史、可恢复；模型 RPM/每日 Token 配额、凭据过滤、`parallel` 自动协作、`escalate` 升级策略，以及执行阶段的 fallback 链。
- 项目验证：成功修改项目文件后按“关闭 / 快速 / 完整”设置执行已确认的检查命令，失败在原智能体会话内最多修复配置的轮数，共享原有工具、费用和时间预算。随后独立模型读取实际改动进行复核；界面与 trace 分别保存检查、修复、取消和未验证状态。
- 模型设置、连接测试、输出复制和 Markdown 导出。
- 运行监测页面：运行轮次、成功率、平均耗时、预估成本、模型分布、最近运行和可筛选/展开的调用链；减少重复信息，把详情集中在单条运行的 trace 中。
- 自成长引擎：按实际路由出的任务类型记录成功与失败、成本、延迟、审计质量和用户评分，并动态调整路由权重。
- 桌面页面通过主进程审批和项目沙箱执行命令。交互终端后端保留为独立模块，桌面端已移除对应的预加载接口和 IPC 处理器。
- 智能体内核：任务执行通过 [Pi SDK](https://pi.dev/)（`@earendil-works/pi-coding-agent`）完成工具调用循环、流式输出和多轮上下文。模型与密钥仍由 newAi 加密保存，每轮在内存中新建 Pi 会话，不读写 `~/.pi`。
- 内置工具：`web_search`、`web_fetch`、`read` / `ls` / `grep` / `find`，项目符号索引 `code_symbols`、可选本机语义检索 `code_search`；选定项目后提供 `write` / `edit`、`run_command` / `process_status` / `process_list` / `stop_process`；长期记忆工具为 `remember` / `recall` / `forget`。检索遵循项目忽略规则和凭据文件策略，符号索引后台增量更新；语义检索默认关闭，只连接显式选择的本机 embedding 模型。文件读取会记录内容指纹：覆盖写入前若发现文件已被编辑器、格式化工具或其他会话改动，会阻止写入并提示模型重新读取，而不是静默覆盖。
- 创建网页时，模型可以写入代码、启动服务、验证 HTTP 返回并报告访问地址。命令使用选定项目作为工作目录，经过统一审批策略与沙箱包装；macOS 使用系统文件和网络约束，Linux 在可用时使用 bubblewrap，Windows 或平台探测失败时在设置与 trace 中显示不可用原因。网络策略和额外可写目录可在运行设置中配置，macOS 当前实现不代表完整系统隔离。
- 后台服务在单轮回复完成后继续运行，可在后续对话中要求查询或停止，也可以通过输入栏「进程」查看运行状态、URL、日志尾部并手动停止；退出应用会清理它启动的进程。停止任务时，如果本会话启动过后台服务，会询问“停止全部 / 保留运行”。普通命令支持取消、超时和有限日志。并行分析子模型保留只读工具，最终执行模型负责修改及执行。
- 执行期间可点击输入框右下角的停止按钮；取消或连接失败时保留已生成的回复及工具状态。智能体执行默认不设轮数、次数、输出总量或时间上限，工具与模型调用以成功或失败结束；模型单次回复达到输出上限时会自动从断点继续；生图等待不计入项目计时，也不参与费用预算。正常回复结束后仅保留最终答案。Bing 页面解析可能受网络或页面变化影响，失败会作为工具结果反馈给模型。
- 扩展设置：管理技能目录、预览导入与启停，配置 stdio / HTTP MCP 服务、测试连接并查看日志，设置逐工具信任。MCP 环境变量和请求头加密保存，界面显示掩码。全局规则可编辑，项目 `AGENTS.md` 和 `.newai/rules/`、`.newai/hooks.json` 按文件内容指纹确认后加载；临时会话规则随请求传递。声明式 Hooks 支持工具前后与运行首尾事件，命令共用审批、超时和沙箱。
- 统一模型调用：执行与规划、摘要、复核、记忆提取及连接测试共享 Pi 协议实现。设置 →“运行与权限”中的“辅助模型调用通道”可切换辅助调用的旧版兼容回退。辅助调用可保留兼容网关和 Anthropic 地址的查询参数；Google 辅助调用使用带查询参数的地址时需选择旧版回退，执行模型建议使用不带查询参数的服务根地址。
- 计划可见与确认：自动执行、确认后执行、仅规划三种方式；会话显示持久化计划卡片，可确认、编辑或取消，执行时按步骤更新状态。默认方式在运行设置中保存，输入框可为本轮覆盖。
- 项目上下文：从只读选定工作区生成文件树和限额文本上下文，默认发送但可在输入框显式关闭；统一跳过二进制、`.env*`、`.npmrc`、`.netrc`、`credentials`、`.aws/`、`.git/` 等凭据与版本库元数据，并用 `<project_context untrusted="true">` 标注为不可信数据。
- 命令执行必须选择项目，并按当前权限和工具信任规则审批；具备超时、取消、环境过滤和输出上限。每次 `write` / `edit` 会在写入前保存原内容（单文件不超过 1 MiB，保留 30 天），任务结束后回复下方显示“本轮修改了 N 个文件”，可查看清单并一键撤销；撤销会跳过本轮之后又被修改的文件、凭据文件和超过快照上限的文件。主进程只接受应用自身页面发来的 IPC，任务请求先做结构校验，每个页面每分钟最多提交 20 次任务；同一会话始终只有一个任务在运行，被取消或替换的上一轮结束前不会启动新的一轮，避免两次执行交错修改同一项目。

### 配置非官方或自托管模型

在设置弹窗中点击左侧“添加模型”，选择“兼容网关”“自建反代”或“本地 Ollama / vLLM 实例”，填写服务地址和 API Key（本地或免密服务可留空），再点击“获取模型”同步模型列表，或手动添加服务端提供的模型 ID。地址可以填写 `/v1` 基础地址，例如 `https://gateway.example/v1`，应用会自动请求 `/chat/completions`；也可以直接填写完整的 `.../chat/completions` endpoint。API 地址与 API Key 分开保存，因此没有 Key 的本地服务重启后仍会保留地址。

设置弹窗支持端点搜索、模型卡片与下拉选择、采样温度和 32k / 64k / 128k 上下文预设。温度范围为 0–1.5，Anthropic 为 0–1；DeepSeek 深度思考模式会发送 thinking 参数，开启时服务端忽略温度。高级配置保留自定义上下文长度、最大输出 Token、综合智能度、代码/推理/创意/视觉/长上下文能力评分、输入和输出价格、路由优先级及请求限额。API Key 使用 AES-256-GCM 加密后保存；自定义服务按 OpenAI-compatible Chat Completions 协议发送请求。

“连通测试”和“获取模型”使用当前表单中的地址、模型与新密钥；留空的密钥只在 scheme+host+port 未变化时复用已加密保存的凭据，修改端点域名后必须重新输入 Key。没有密钥的内置模型不会被标记为远程连接成功，也不会进入路由。点击“设为主力路由”并保存后，任务执行优先使用该模型；再次点击主力按钮并保存可恢复自动路由。主力选择与端点参数一起事务保存，失败时保留旧配置。取消或按 Esc 关闭会丢弃未保存的修改。

### 图片生成与媒体调度

文本、图片和视频模型统一在“模型与端点”配置用途。图片用途选择 OpenAI Images 协议，填写中转站的服务根地址（如含 /v1 的 baseURL）、API Key 和模型 ID；也可填写完整 images/generations 地址。图片配置不要使用 chat/completions 地址。当前支持返回 Base64 的静态 PNG/JPEG/WebP 图片生成，视频用途可保存，但实际视频协议尚未接入。

每个图片模型填写单次预估费用用于运行预算预留。图片模型数量不限，不绑定某一个默认模型；按已启用的图片用途、协议、操作评分、优先级和请求的成本/速度偏好动态选择。尺寸、格式、质量和透明背景的实际支持范围由模型与服务端决定，项目不要求填写能力声明，也不使用旧版保存的 `limits` 元数据拒绝生成。

直接生图和 `request_media` 透传显式指定的尺寸、格式、质量与背景参数，不从自然语言中强制提取并注入参数。`aspectRatio` 和 `minSize` 作为提示词需求转交给模型，不在本地选择尺寸档位。服务端返回有效图片后，应用保存真实图片及其实际尺寸、格式等元数据，交由大模型评估是否满足任务要求；服务端拒绝则返回实际接口错误。

明确的纯生图请求直接进入媒体服务；开发页面等复合任务仍走文本自由调度，执行者和只读子智能体可以用 request_media 提交生成要求，程序选型后返回共享资产。get_media_job 查询已有任务，materialize_asset 在具备项目写权限时导出真实文件。媒体生成和文本执行共用根任务预算与现有工具权限；桌面固定模型仅约束文本任务，CLI 的 --model 是本轮严格指定。

图片保存在本地，结果卡支持预览、打开与另存；会话恢复时从持久化媒体任务补齐结果。提交结果未知不会自动切换供应商或重新生成；必需素材失败时整轮标为未完成。图片连通不使用文字测试，首次生成才验证真实图片接口。单次费用是配置估计，不等同供应商账单。

详见 [媒体调度方案](outputs/MEDIA-GENERATION-PLAN-2026-11-11.md)。

### 调用链、记忆与路由规则

- 调用链保存在 `metrics.db` 的 `runs`/`spans` 表；会话只保存最近一次 `runId`，重新打开会话会按该 ID 读取时间线。
- 上下文摘要保存在 `sessions.db` 的 summary 列；长期记忆保存在 `<userData>/memory.db`，当前版本隐藏入口但保留数据；不会保存疑似 API Key/私钥的内容。
- 路由规则文件为 `<userData>/routing-rules.json`，示例：

```json
{
  "version": 1,
  "defaults": { "strategy": "single" },
  "rules": [
    {
      "id": "code-high",
      "enabled": true,
      "priority": 10,
      "when": { "taskTypes": ["code"], "complexity": ["high"] },
      "then": {
        "primaryModelId": "deepseek-chat",
        "strategy": "plan+verify",
        "fallbackModelIds": ["backup-model"]
      }
    }
  ]
}
```

规则只从已启用、有可用凭据、未超配额且满足上下文窗口的模型中选择；高复杂度代码在无规则时也默认进入 `plan+verify`。固定模型与显式规则优先，规划建议不覆盖已选执行模型或任务分类。显式 `single` 规则不添加规划；高复杂度任务或 `plan` / `plan+verify` / `parallel` / `escalate` 策略按需规划，运行设置可关闭这一步而保留已有协作者。`parallel` 规则未指定协作者时会自动选择 2 个低成本可用模型；`escalate` 规则在验证发现问题时优先用 fallback 链中的更强模型修订。每次 run 默认使用 $0.25 的累计预估费用上限和 10 分钟时限，可在“设置 → 运行与权限 → 任务路由与模型分工”修改。每个真实模型请求前检查剩余额度并限制输出，每次回复增量记账，停止后保留阶段结果和指标；该费用依据配置单价估算，包含缓存输入的统一计价，不等于服务商账单或绝对硬封顶。调用链保存实际请求型号与当时费率快照；旧内部配置 ID 不代表上游型号。

### 本机 Ollama 路由

安装并启动 Ollama，准备支持结构化聊天输出的本地模型。在“设置 → 运行与权限 → 任务路由与模型分工”选择“本机 Ollama”，填写服务根地址（如 `http://127.0.0.1:11434`，不含 `/v1`）、分类模型 ID 和等待上限，检测后保存。分类模型 ID 应填写本机已经安装的模型。

配置保存为 `<userData>/routing-settings.json`，与回答模型配置独立；默认仍使用规则分类，Ollama 为可选依赖。后台预热期间和服务不可用时立即回退规则；用户取消会终止分类请求。第一阶段仅连接 loopback 本机地址，云端分类服务仍属于后续部署方案。分类置信度、实际后端、耗时、模型版本、提示词版本及回退原因记录在调用链中。

运行监测中的“纠正分类”会展示将保存的任务和必要上下文，确认后写入 `<userData>/routing-corrections.json`（最多 500 条）；后续按相关性挑选有限示例。分类提示词版本为 `v3` 或 `v3+feedback`，反馈影响的是推理上下文，不会自动微调模型。完整权重训练、自动提示词候选评测和云端部署尚未实现。

长期记忆的自动提取默认关闭，开启后会额外调用一个低成本模型；提取内容仍会经过密钥过滤，可在记忆面板中逐条删除或整体清空。

## 开发

需要 Node.js 22–24。Node.js 22 LTS 是推荐版本；Node.js 24 也受支持，项目安装脚本会绕过 Electron `extract-zip` 在部分 Node 24 环境中的解压卡死。

```bash
npm install
npm run dev
```

如果 Electron 启动时提示二进制安装不完整，先运行：

```bash
npm run doctor:electron
```

`doctor:electron` 会从 `@electron/get` 的校验缓存取得对应版本，并使用系统 `unzip` 恢复 Electron 可执行文件，安装后的 `postinstall` 会自动执行这一步。SQLite 使用 `better-sqlite3` 13 自带的 Node-API 原生模块，可供宿主 Node 与 Electron 共用，无需切换 ABI 或本机 C++ 编译。

生产构建：

```bash
npm run build
npm start
```

本机目录打包（不签名）使用：

```bash
npm run pack:dir
```

打包会先检查 Electron 二进制并编译应用代码；发布检查会在 Electron 中实际打开内存数据库，确认 SQLite 原生模块可用后才生成应用包。打包只包含 `dist/main`、`dist/preload` 和 `dist/renderer`，因此 `dist` 中已有的其他平台安装包不会被再次收入新包。

安装器目标已配置为 macOS `dmg`/`zip`、Linux `AppImage`/`deb` 和 Windows `nsis`/`zip`；跨平台构建需要在对应系统或 CI runner 上执行。

质量检查：

```bash
npm run lint
npm test
npm run test:coverage
npm run build
npm run smoke:renderer
npm run release:check
```

`smoke:renderer` 以隐藏窗口加载构建产物，验证 sandbox preload、CSP、window.amd/trace/memory 与根节点渲染；没有图形环境时需要 Xvfb 或本地桌面会话。

CI 见 `.github/workflows/ci.yml`：Node 22/24 上执行类型检查、带阈值的全项目覆盖率测试和构建。覆盖率从 `src/**` 全量统计。直接依赖固定为锁文件中的精确版本，`node scripts/check-dependencies.mjs` 检查清单与锁文件一致；`--suggest` 只读输出当前解析版本，供明确更新依赖时参考。生产依赖检查使用 `npm audit --omit=dev --audit-level=high`。

首次打开应用后，在“模型与设置”中添加或编辑模型。内置提供商必须配置 API Key 才会参与路由；自定义 OpenAI-compatible 服务会按其 API 地址发起请求，API Key 可留空。应用会把数据库保存到 Electron 的用户数据目录，密钥包装文件名为 `credentials.key`。如果系统密钥库不可用，应用仍会启动并提示受影响的模型；可设置 `AMD_ENCRYPTION_KEY`（64 位 hex 或 base64 的 32 字节密钥）作为恢复路径。

### 命令行与离线评测

CLI 与桌面端共用核心运行链路，默认使用独立的 `~/.newai` 数据目录。构建后可执行：

```bash
npm run build:cli
node dist/cli/newai.mjs --help
node dist/cli/newai.mjs models list
node dist/cli/newai.mjs run "说明项目入口" --project . --json
node dist/cli/newai.mjs eval --smoke
```

模型配置、临时环境变量、终端审批、取消、JSON 事件和共享数据密钥见 [CLI 使用说明](docs/CLI.md)；任务结构、检查器和模型对比见 [离线评测说明](eval/README.md)。框架回放只验证评测流程；真实模型质量和费用需要使用已配置模型运行并查看报告。

## 目录

- `src/main`：Electron 主进程、IPC 和应用生命周期。
- `src/preload/preload.ts`：Electron-Vite 预加载入口；context bridge 和 IPC 暴露实现在 `src/main/preload.ts`。
- `src/core/models`：模型类型、注册表和预置配置。
- `src/core/storage`：SQLite 模型持久化和凭据加密。
- `src/core/routing`：可选 Ollama 分类后端、独立运行设置、启发式路由与确定性 fallback。
- `src/core/project`：项目目录扫描、忽略规则、文本提取和上下文预算。
- `src/core/codebase`：后台符号索引、可选本机语义检索和增量缓存。
- `src/core/security`：审批分类、规则和工具信任、平台沙箱。
- `src/core/verify` / `src/core/hooks`：真实项目检查与有界修复、声明式钩子执行。
- `src/core/bootstrap` / `src/cli`：无 Electron 的核心组装和命令行入口。
- `src/core/planning`：计划存储、确认与步骤状态。
- `src/core/context`：上下文装配、token 预算、确定性摘要和 LLM checkpoint。
- `src/core/memory`：长期记忆 SQLite 存储与检索。
- `src/core/trace`：run/span 调用链类型与记录器。
- `src/core/providers`：统一模型调用适配层。
- `src/core/agent`：Pi SDK 接入（模型映射、系统提示词、`AgentRuntime`）。
- `src/core/tools`：内置工具与可插拔搜索后端（`search/`）。
- `src/core/observability`：调用、Token、成本和延迟指标。
- `src/core/audit`：独立模型审计、本地静态 fallback 和只追加哈希链日志。
- `src/core/growth`：性能档案与滑动平均反馈学习。
- `src/core/tty`：终端会话生命周期管理。
- `src/renderer`：React 工作台和设置页面。
- `test/unit`：加密、重启持久化和注册表测试。
- `eval`：隔离项目快照的离线评测任务、检查器与报告。
- `docs/INDEX.md`：项目文档与验收资料索引。

项目文档仍保存在 `outputs/`，其中 [Electron 安装诊断](outputs/08-ELECTRON-INSTALL-DIAGNOSTICS.md) 记录了二进制解压卡死、原生 ABI 和发布验证的处理方式。
